@@98|TCP vs UDP
E: TCP provides a reliable ordered byte stream with congestion and flow control. UDP provides datagrams without built-in delivery, ordering, or retransmission guarantees. UDP sends bounded datagrams with minimal transport state. Protocols built on UDP, such as QUIC, can add reliability, encryption, streams, and congestion control.
W: A TCP receiver gets bytes for the end of a message before earlier bytes; it waits for the missing bytes before delivering the contiguous stream. A UDP receiver may receive a later datagram first and choose to discard, reorder, or process it according to the application protocol.
T: TCP is appropriate for many reliable transfers. UDP can suit real-time media, discovery, or custom transports, but reliability must be designed where needed. TCP does not guarantee the remote application committed an operation merely because bytes were acknowledged.
F: Assuming one send equals one TCP receive breaks framing. Assuming UDP is always faster ignores workload and implementation. Large datagrams risk fragmentation or path MTU problems; application protocols need size strategy and loss handling.
